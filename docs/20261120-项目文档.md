## 一、项目概览

### 1.1 产品定位

面向个人与家庭的衣物收纳微信小程序：拍照入库、多衣橱分类管理、搭配收藏、一键搭配、穿搭日历与家庭共享，帮助用户「找得到衣服、搭得出一套」。

### 1.2 技术栈

| 项目 | 说明 |
| --- | --- |
| 框架 | 微信小程序原生框架（WXML / WXSS / JS / JSON） |
| 后端 | 微信云开发（云数据库 + 云存储），无自建服务 |
| 云环境 ID | `cloud1-d5ghmekgecd229e76` |
| 云数据库集合 | `wardrobe_data`（每个用户一条文档） |
| 本地缓存 | `wx.setStorageSync`，Key：`magic_wardrobe_data_v2` |
| 第三方依赖 | 无（图标为内联 SVG base64，不使用图标库） |
| 主题色 | 主紫 `#7b5bd6`、浅紫 `#a189ec`、粉色 `#ffe9f1`；正文 `#2b2440`、次级 `#9c95b0` |

## 二、功能清单

### 2.1 首页

- 顶部渐变问候卡：按时段生成问候语、显示当天日期与星期、头像。
- 数据统计卡：衣橱单品总数、本月新增数、衣橱数量。
- 最近添加：按 `addedAt` 倒序取前 6 件展示缩略图，点击进入单品详情；无单品时整页空态。
- 三个快捷入口：拍照收纳、我的衣橱、我的搭配，均使用紫色 SVG 图标。
- 空态：单品为 0 时展示「欢迎来到你的数字衣橱」，主按钮「开始添加」跳转添加单品页。
- 已移除「今日灵感」区块（v1.0.0 后置）。

### 2.2 衣橱（单品列表）

- 排序规则：喜欢优先，其次按加入时间（`addedAt`）倒序。
- 衣橱筛选：全部 / 指定衣橱 / 喜欢专页（由「我的 → 我喜欢的单品」注入 `__favorite__` 过滤条件）。
- 分类筛选：全部、上衣、裤装、裙装、外套、鞋履、包袋、配饰。
- 关键词搜索：匹配名称、颜色、品牌。
- 交互：点击卡片进详情、点击喜欢切标记（Toast 反馈）、空状态引导去添加。
- 空态文案：「衣橱还是空的 / 拍下第一件衣服，开始建立你的数字衣橱。」，按钮「添加第一件单品」。
- 空态额外提供「载入示例数据」按钮：二次确认后写入示例单品与衣橱，是唯一写入示例数据的入口。

### 2.3 添加 / 编辑单品

- 照片：调用 `wx.chooseMedia`，支持拍照或相册；选图后必须进入图片裁切页（3:4），确认后回填裁切结果，不允许跳过直接上传；未选图时按分类使用默认占位图。
- 隐私授权：首次调用相册/相机弹出 `privacy-popup`；拒绝后仍可手动填写保存，图片位保持占位。
- 表单字段：名称（必填）、衣橱（必选，默认第一个）、分类（必填）、颜色（6 种预设）、适合季节（多选，按当前月份单季预选：3–5 春、6–8 夏、9–11 秋、12–2 冬）、品牌（选填）、搭配备注（选填，最多 60 字）。
- 无衣橱时展示「还没有衣橱，先创建一个」提示，保存时引导跳转添加衣橱页。
- 保存按钮在「名称 + 分类」齐全时才可点击。
- 图片处理：裁切导出（JPEG 质量 80、1200 × 1600）→ `saveFile` 持久化 → 上传前自适应压缩（长边 ≤1600；体积 >300KB 时按 quality 80/70/62/55 逐级重压至达标）→ 云存储上传，并发上限 5；最终保存 `cloud://` 文件 ID。历史本地图片迁移到云存储时同样先压缩。
- 上传失败：保留本地路径，`syncState` 标记 `pending`，toast「已保存到本机，稍后自动同步」。
- 编辑模式：`options.id` 存在时回填表单，保留原 `favorite`、`addedAt`，保存后 `wx.navigateBack`。

### 2.4 单品详情

- 展示：大图、名称、分类、颜色、季节、品牌、备注、所属衣橱。
- 未同步提示：`syncState === 'pending'` 时展示「图片未同步 · 联网后自动上传」。
- 操作：切换喜欢、编辑（跳转添加页）、转移衣橱（ActionSheet 选择目标衣橱）、删除（二次确认）。
- 边界：仅有一个衣橱时提示先添加衣橱；转移到当前衣橱时提示已在其中。

### 2.5 衣橱管理

- 列表展示每个衣橱的封面、名称、位置、单品数量；名称为空时显示「未命名衣橱」。
- 封面选填：未选择时 `cover` 为空字符串，前端回落内置紫色渐变默认封面（不使用外链图片）；上传失败保留本地路径、衣橱正常保存并提示「已保存，封面未同步」。
- 新增 / 编辑衣橱：名称（必填，1–16 字符，去首尾空格）、位置、封面图（拍照/相册后进入裁切页，15:8，导出 1600 × 853、质量 80）。
- 重名校验：比较前 `trim` 并转小写，命中已有衣橱时提示「已存在同名衣橱」且不保存；编辑时排除自身。
- 删除衣橱：二次确认，文案包含件数与目标衣橱名；单品转移到剩余衣橱中 `createdAt` 最早的一个（旧数据无 `createdAt` 按 id 升序），并提示转移数量；仅剩一个衣橱时禁止删除。
- 空衣橱直接删除，不出现转移说明；删除后衣橱筛选自动回退「全部」。
- 点击衣橱进入该衣橱的单品列表（通过 `globalData.wardrobeFilter` 传递筛选条件）。
- 家庭共享入口与开关已隐藏。

### 2.6 隐私保护

- 全局 `components/privacy-popup`：首次调用相册/相机时弹出，含《用户隐私保护指引》链接。
- 同意：`open-type="agreePrivacyAuthorization"` 按钮放行原接口。
- 拒绝：授权接口返回失败，添加单品/衣橱降级为手动填写，不阻断保存。
- 设置页提供协议入口与「删除全部数据」。

### 2.6.1 新手引导与教学文案

- 首次启动条件：`onboardingDone !== true` 且 `items.length === 0`；已有单品的账号不展示。
- 引导页为全屏 4 张卡片：首页 → 衣橱 → 添加单品 → 搭配，支持手势左右滑动，也可点「下一步」切换。
- 最后一张按钮为「开始使用」；第一张右滑无动作，最后一张左滑不循环。
- 右上角常驻「跳过」，点击立即关闭并写入完成标记，后续不再展示。
- 跳过与「开始使用」都会写入 `onboardingDone: true` 并随云端同步；系统返回关闭不写标记。
- 设置页「新手引导」可随时重看，重看不改变完成状态。
- 引导页不依赖网络、隐私授权与云端，离线可用；卡片示意图为 CSS 线框占位。
- 首页、衣橱、搭配空态文案统一按需求包 R16 定稿文案。

### 2.7 搭配（我的搭配）

- 我的搭配：横向滚动卡片，展示自建搭配的前 3 张单品图与名称；点击进详情，支持删除。
- 新建搭配：跳转搭配编辑页。
- 空态：文案「还没有搭配 / 先收纳至少 2 件单品，再把它们组合成一套搭配。」，按钮「去添加单品」。
- 已移除一键搭配、场景筛选与内置灵感列表。

### 2.8 新建 / 编辑搭配

- 5 个槽位：上装（含裙装）、下装、外套、鞋履、饰品（包袋/配饰）。
- 交互：点击槽位切换当前编辑槽，选择单品填充；再次点击已填充槽位可清除。
- 命名：可留空，默认「我的搭配」。
- 校验：至少选择 2 件单品才能保存。
- 编辑：携带 `options.id` 进入时回填名称与已选单品，保存调用 `updateLook`。

### 2.9 搭配详情

- 数据来源：用户自建搭配（`looks`）。
- 展示：标题、封面、作者「我的搭配」、单品数量与创建日期、单品清单。
- 失效单品：单品被删除后显示「单品已删除」占位，可进入编辑移除。
- 操作：编辑（跳转 build-look）、删除（二次确认，不影响单品）。

### 2.10 穿搭日历（隐藏）

- 页面代码保留，但「我的」页无入口，属于不可见、不可达的隐藏功能。
- 按单品 `addedAt`（入库日期）倒序分组，显示「月-日 + 星期」。

### 2.11 我的（个人中心）

- 头像与昵称（当前固定：`衣橱主人` + 占位头像）。
- 统计：衣橱单品数、衣橱数量、我的搭配数。
- 菜单：我喜欢的单品、衣橱管理、设置、关于。
- 等级、家庭共享、穿搭日历入口已隐藏。

### 2.12 设置

- 统计：单品、衣橱、搭配、喜欢数量。
- 隐私保护指引：调用 `wx.openPrivacyContract` 打开协议。
- 清空单品与搭配：清空单品、搭配、收藏，保留衣橱与家庭成员。
- 删除全部数据：二次确认后删除本地缓存、云端记录与云存储图片。
- 关于：版本与功能说明弹窗。
- 页脚说明：数据已通过微信云开发同步，换设备登录也能看到。

### 2.13 视觉与图标体系

- 全部图标为内联 SVG base64，定义在 `app.wxss`，类名前缀 `mw-icon-*`，基础类 `.mw-icon` 统一 `background-size: contain`。
- 已覆盖：heart、hanger、people、calendar、gear、pin、camera、sparkle、sparkle-light（白色）、refresh、trash、info、image。
- 首页快捷入口、我的页菜单、设置页、添加衣物页、tabBar 均无彩色 emoji。

## 三、核心流程

### 3.0 首次启动引导

```
小程序启动 → 首页 onLoad
  └─ 等待 app.globalData.readyPromise（云端合并完成）
       └─ store.isOnboardingNeeded()
            ├─ onboardingDone === true → 不展示
            ├─ items.length > 0 → 不展示（老用户）
            └─ 否则 → wx.navigateTo('/pages/onboarding/index')
                 ├─ 左右滑动 / 点「下一步」：4 张卡片同步切换
                 ├─ 点「跳过」→ completeOnboarding() → 返回首页
                 ├─ 第 4 张「开始使用」→ completeOnboarding() → 返回首页
                 └─ 系统返回 → 不写标记，下次冷启动仍展示
设置 → 新手引导（preview=1）→ 只浏览，不改变完成状态
```

- `onboardingDone` 随云端同步，合并取或，任一设备完成即不再展示。
- 引导页不依赖网络、隐私授权与云端。

### 3.1 启动与数据同步

```
小程序启动
  └─ app.onLaunch
       ├─ 注册 wx.onNeedPrivacyAuthorization（隐私授权监听）
       └─ store.init()
            ├─ 读取本地缓存（magic_wardrobe_data_v2），缺失时创建空状态
            ├─ wx.cloud.init(env)
            ├─ 查询 wardrobe_data where _openid = 当前用户，limit 1
            │    ├─ 云端无记录 → 本地有数据才推送（空数据不写云端）
            │    ├─ 云端有记录、本地无数据 → 直接采用云端
            │    └─ 两边都有数据 → mergeStates 按 id 取较新，合并后推送一次
            │         └─ 本地有贡献 → toast「已合并本机与云端数据」
            └─ 本地图片迁移到云存储（USER_DATA_PATH 开头的图片）
  └─ globalData.cloudEnabled = ready
```

- 页面读取统一走同步方法 `store.getState()` / `store.getSortedItems()`，渲染不等待网络。
- 任何写操作：先写本地缓存（`updatedAt = Date.now()`），再通过 `writeChain` 串行 `pushCloud()`。
- 云端不可用（非云开发环境、初始化失败）自动降级为纯本地模式，不影响使用。

### 3.2 新增单品

```
首页「拍照收纳」/ 衣橱「添加」 → 添加衣物页
  → 拍照或从相册选择（chooseMedia）
  → 首次使用相册/相机：弹出隐私弹窗
      ├─ 同意 → 微信放行，继续选择
      └─ 拒绝 → 接口失败，保持占位图，可手动填写保存
  → 进入图片裁切页（3:4 固定取景框，可拖动/双指缩放/重置）
      ├─ 取消 → 返回添加页，不产生图片
      └─ 确认 → canvas 2d 导出取景框画面（1200 × 1600、JPEG 质量 80）→ 回填缩略图
  → 填写名称、选择衣橱/分类/颜色/季节、可选品牌与备注
  → 点击「加入我的衣橱」
      → 校验名称与分类
      → store.saveImage：本地 saveFile → 压缩 → 云存储 uploadFile（并发上限 5）
      → 返回 cloud:// 或本地路径，本地路径标记 syncState=pending
      → store.addItem（本地缓存 + 云同步）
      → Toast「已加入衣橱」/「已保存到本机，稍后自动同步」→ 返回上一页
```

### 3.3 编辑 / 转移 / 删除单品

```
衣橱列表 → 点击卡片 → 单品详情
  ├─ 喜欢：toggleFavorite（本地 + 云端）
  ├─ 编辑：跳转添加页（携带 id）→ 回填 → 保存 updateItem
  ├─ 转移：ActionSheet 选衣橱 → moveItem
  └─ 删除：二次确认 → removeItem → 返回列表
```

### 3.4 衣橱管理

```
我的 → 衣橱管理
  ├─ 新增：填写名称/位置/封面 → addCabinet
  ├─ 编辑：携带 id 回填 → updateCabinet
  ├─ 删除：二次确认
  │    ├─ 仅剩 1 个 → 提示不可删除
  │    └─ 其余情况 → removeWardrobe：单品转移到 createdAt 最早的剩余衣橱
  └─ 点击衣橱 → 设置 globalData.wardrobeFilter → 切到衣橱 tab 并筛选
```

### 3.5 搭配创建与编辑

```
搭配 → 新建搭配
  → 选择槽位（上装/下装/外套/鞋履/饰品）
  → 从同类单品中点选，再次点击取消
  → 输入搭配名称（可空）
  → 点击保存：至少 2 件 → addLook → 返回搭配页
搭配 → 点击搭配卡片 → 搭配详情
  ├─ 编辑：跳转 build-look（携带 id）→ 回填 → updateLook
  └─ 删除：二次确认 → removeLook（单品不受影响）
```

### 3.6 隐私授权

```
调用 wx.chooseMedia
  └─ 微信触发 onNeedPrivacyAuthorization
       └─ app.js 找到当前页 → 调用页面 showPrivacyPopup()
            ├─ 同意（open-type 按钮）→ 微信自动放行原接口
            └─ 拒绝 → app.resolvePrivacy(false) → 原接口 fail → toast 提示可手动填写
```

### 3.7 删除全部数据

```
设置 → 删除全部数据 → 二次确认
  → store.clearAll()
      ├─ 收集 items / wardrobes 中的 cloud:// 文件
      ├─ deleteFile 分批（每批 50 个）删除云存储文件
      ├─ collection.doc(docId).remove() 删除云端记录
      ├─ wx.removeStorageSync 删除本地缓存
      └─ 重置内存状态为空
  → 刷新统计 → toast「数据已全部删除」
```

### 3.8 隐藏功能

- 穿搭日历、家庭共享、等级、一键搭配、今日灵感：入口已移除，页面代码保留，属于不可见、不可达状态。
- 首页、衣橱、搭配、我的四个 tab 均无上述功能入口。

## 四、数据模型

### 4.1 单品 item

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | `c-{timestamp}` |

## 六、未实现内容

### 6.1 功能缺口

| 模块 | 未实现 / 待完善 | 影响 |
| --- | --- | --- |
| 家庭共享 | 入口隐藏，代码保留；邀请码未与真实账号绑定 | 本期不提供真实多账号协作 |
| 穿搭日历 | 入口隐藏，仅按入库日期分组的旧实现 | 本期不作为功能承诺 |
| 等级 | 入口隐藏，等级计算代码已移除 | 本期不提供成长激励 |
| 一键搭配 | 已移除按钮与随机逻辑 | 仅保留自建搭配 |
| 灵感内容 | 首页今日灵感已移除，内置搭配数据文件保留 | 不再展示预置内容 |
| 账号与资料 | 头像、昵称为固定值，不支持修改 | 个人中心不可个性化 |
| 衣橱 | 不支持拖拽排序、不支持衣橱内批量移动 | 大数量整理效率有限 |
| 单品 | 不支持批量选择/删除、无按季节或颜色筛选 | 管理体验待优化 |
| 搜索 | 无搜索历史、无热门词、无结果高亮 | 检索体验一般 |
| 分享 | 未实现 `onShareAppMessage` | 缺少传播入口 |
| 通知 | 未接入订阅消息 | 无召回手段 |
| 数据 | 无导出/导入、无回收站 | 误删只能通过「删除全部数据」重置 |
| 多端 | 删除不传播、时钟依赖、整包推送 | 见 6.2 已知限制 |

### 6.2 技术债与风险

| 项 | 说明 |
| --- | --- |
| 删除不传播 | 无墓碑机制，旧设备可能把已删除单品带回（第二期处理） |
| 时钟依赖 | 合并以客户端 `updatedAt` 为准，设备时钟偏差可能影响新旧判断 |
| 整包覆盖写入 | 云端每次写整份文档，数据量增大后写入成本与冲突概率上升 |
| 失败不重试 | 上传/推送失败只标记与提示，重启后随整份数据再推 |
| 云存储清理 | 仅「删除全部数据」清理文件；单品/衣橱单独删除不清理孤儿文件 |
| 历史图片 | v1.0.0 不重裁历史图片，也不删除被替换的旧封面云文件（由 v1.1.0 清理队列处理） |
| 初始化静默降级 | 云端不可用时用户无感知，仅 `globalData.cloudEnabled` 标记 |
| 权限与索引 | 集合权限需在控制台配置，仓库以 README 步骤固化 |
| 性能 | 列表全量渲染、无分页/虚拟列表，单品上千时可能卡顿 |
| 质量保障 | 无单元测试、无 E2E、无 CI 流程 |
| 合规 | 后台《用户隐私保护指引》需人工配置并提交审核 |
| 版本管理 | 当前改动尚未提交 Git（需确认分支与账号后提交） |

## 七、后续建议（按优先级）

1. 数据同步健壮性：加删除墓碑与版本号，补充失败重试队列。

6. 分享与召回：分享单品/搭配卡片，接入订阅消息提醒整理衣橱。
7. 质量保障：补充自动化测试与 CI，覆盖同步与合并边界。
